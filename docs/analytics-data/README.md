# 팀 공유용 GTM + GA4 Notion 데이터베이스

팀원에게는 GTM 변수나 내부 ID보다 **사용자가 언제 어떤 행동을 하고, 그 행동으로 무엇을 판단할지**가 먼저 보여야 합니다.
따라서 Notion에는 CSV 2개만 가져옵니다.

## 1. Analytics Events

파일: `analytics-events.csv`

Notion에서 **표 데이터베이스**로 가져오고 `이벤트명`을 제목 속성으로 바꿉니다.

### 권장 속성 유형

| CSV 열 | Notion 속성 |
| --- | --- |
| 이벤트명 | 제목 |
| 순서 | 숫자 |
| 사용자 흐름, 퍼널 단계 | 선택 |
| 구현 상태, GTM 상태, GA4 핵심 이벤트, 검증 상태 | 상태 또는 선택 |
| 최종 수정일 | 날짜 |
| 나머지 | 텍스트 |

### 팀에서 사용할 보기

1. **전체 이벤트 — 표**
   - `순서` 오름차순
   - 기획·개발·마케팅이 함께 보는 기본 화면
2. **지원자 퍼널 — 리스트**
   - `사용자 흐름 = 지원자`
   - `순서` 오름차순
3. **공연사 퍼널 — 리스트**
   - `사용자 흐름 = 공연사`
   - `순서` 오름차순
4. **작업 현황 — 보드**
   - `구현 상태`로 그룹화
5. **핵심 전환 — 표**
   - `GA4 핵심 이벤트 = 지정 예정` 또는 `지정 완료`
6. **검증 필요 — 리스트**
   - `검증 상태`가 `Tag Assistant 확인`이 아닌 이벤트

## 2. Analytics Change Log

파일: `analytics-change-log.csv`

Notion에서 **표 데이터베이스**로 가져온 뒤, 팀이 실제로 보는 기본 화면은 **리스트 보기**로 설정합니다. `변경사항`을 제목 속성으로 바꿉니다.

### 권장 속성 유형

| CSV 열 | Notion 속성 |
| --- | --- |
| 변경사항 | 제목 |
| 날짜 | 날짜 |
| 순서 | 숫자 |
| 구분, 상태 | 선택 |
| 관련 링크 | URL 또는 텍스트 |
| 나머지 | 텍스트 |

### 팀에서 사용할 보기

1. **최신 변경 — 리스트**
   - `날짜` 내림차순
   - 같은 날짜에는 `순서` 내림차순
2. **진행 중 — 보드**
   - `상태`로 그룹화
3. **변경 달력 — 캘린더**
   - `날짜` 기준

## 관리 순서

새 이벤트나 수정 사항은 다음 순서로 관리합니다.

1. Analytics Events에 먼저 한 행을 추가하고 `구현 상태`를 `예정`으로 둡니다.
2. 코드 구현 후 `구현 완료`로 변경합니다.
3. GTM 설정 후 `GTM 상태`를 변경합니다.
4. Tag Assistant와 GA4에서 확인한 뒤 `검증 상태`를 변경합니다.
5. 변경 내용을 Analytics Change Log에 한 행 추가합니다.

변경 이력은 과거 행을 지우지 않고 새 행을 추가합니다.

## 팀 공통 원칙

- 이벤트명과 주요 데이터는 프로토타입에서 운영까지 가능한 한 유지합니다.
- 이름, 이메일, 전화번호, 자유 입력 답변, 파일명, 내부 메모는 GA4로 보내지 않습니다.
- `application_submitted`와 `recruitment_created`는 GA4 핵심 이벤트로 관리합니다.
- GTM 태그·트리거·변수처럼 개발자만 필요한 상세 설정은 `docs/analytics.md`에서 관리합니다.
- GTM이 게시되기 전까지 `GTM 상태`는 `초안 완료·미게시`입니다.
